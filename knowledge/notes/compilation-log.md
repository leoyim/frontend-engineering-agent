### 标注约定

编纂章节的每一章，头部都给出「本章定位 / 对应地图节点 / 前置 / 规范引用约定 / 读完能做到」。技术结论按两类标注：

| 标注 | 含义 | 出现范围 |
|---|---|---|
| 【补充背景】 | 由编纂者撰写，无课程批改记录 | **新撰章节整章** |
| 【待验证】 | 随浏览器 / 搜索引擎 / 运行时的策略变化而变化的推断 | 就地标注 |

**【已学】不会出现在新撰章节中** —— 它专指"课程讲过且经批改确认"。

### 规范引用方式

统一**按条款名引用，不写节号**。理由：节号在规范版本间会变动，条款名更稳定。

| 领域 | 引用形态 | 例 |
|---|---|---|
| Web 平台 | WHATWG 规范的条款名 | HTML Standard《Event loops》、ECMA-262《Cyclic Module Records》 |
| HTTP | RFC 名称 | RFC 9111《HTTP Caching》 |
| 有官方文档但无标准化组织规范的工具 | 官方文档 | TypeScript（`tsconfig` 参考）、Node.js（模块解析）、Git（Pro Git） |

**第三条容易被忽略**：TypeScript、Node.js、Git、npm 都不是标准化组织规范定义的，涉及"以谁为准"的判断时结论会不同。各章头部的「规范引用约定」块会显式说明这一点。

### 5.4 核验附带发现（不影响结论，但值得知道）

- **ECMA-262「ResolveExport」存在同名多处**：§16.2.1.7.2.2（Source Text Module Record）与 §16.2.1.8.4.3（Synthetic Module Record）各有一处，指向时需区分宿主记录类型。
- **CSS Containment Level 3 的定位偏弱**：它是探索性草案且是 diff spec。容器查询的**稳定参考应是 Level 2**（L3 正文将 L2 文本合并后才会进 CR）。这条修正了正文里"用前查支持度"之外的一个认知。
- **CSSOM View §11 Geometry 未完成**：`GeometryUtils`（`getBoxQuads` 等）在规范中仍是占位与待办注释，不适合作教学引用点。几何接口的稳定部分是 §6 的 `getBoundingClientRect()` / `getClientRects()`。
- **HTML Standard 与 DOM Standard 是 Living Standard**：条款名会随更新变动（本例核验时两者分别在 10-14、10-15 更新过）。这正是本书采用"条款名引用、不写节号"的理由 —— 但**条款名本身也会变**，所以仍建议定期复核。
